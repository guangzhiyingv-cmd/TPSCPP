# 角色与战斗进度

截至 2026-11-24，[角色与战斗设计](CombatDesign.md)中的角色、武器、GAS、动画和 HUD 路径已按当前工作树核对。现有资产包含五种具体武器蓝图、两张数据表，以及开火、换弹、肩射和 ADS 输入动作。工作区待办里的武器数据表和 GAS 已有实现；通用弹药拾取物、类 PUBG 背包仍是待办想法，尚无对应设计。

## 接手续查

按改动范围打开实现专题：[输入与角色表现](Combat/Character.md)、[枪械数据与射击](Combat/Weapons.md)、[伤害与复制](Combat/Damage.md)。

| 现象 | 先检查的接口或资产 |
| --- | --- |
| 能出现拾取提示，但武器没有挂到手上 | 核对角色自定义网格的组件标签、`hand_rSocket` 和服务端当前重叠武器；如果只有远端异常，查 `OnRep_EquippedWeapon`。 |
| 枪械参数与预期不符，或只见抛壳未见子弹 | 先查表句柄、实际行名及加载错误；投射物武器还需要 `ProjectileClass` 和 `MuzzleFlash`。散布要区分普通准星采样与霰弹服务器锥角。 |
| 重生后状态、血量条或动画异常 | 检查同一 PlayerState 上的 ASC 是否已绑定新 Pawn、生命委托和动画映射是否初始化。授予能力的防重标记在角色实例上，连续重生时需检查 ASC 内的能力规格数量。 |
| 只有远端不显示命中特效 | 分别检查服务器是否命中、环境与角色 Cue 的目标、批量消息内的位置和特效资源。历史排查见 [GAS 迁移笔记](GAS_Notes.md)。 |

## 双端回归场景

在 GameLevel 打开双人监听服务器 PIE，让主机和远程客户端各做一次操作方。以下是当前版本待记录的运行结果。

| 场景 | 两端观察点 |
| --- | --- |
| 装备与切换状态 | 只有靠近者看见拾取提示；装备后对方能看到手持武器。肩射按住、ADS 切换、冲刺转开火时，检查自己的镜头与对方看到的姿态。 |
| 三种命中方式 | 手枪验证即时命中；霰弹用角色和墙面同时覆盖散布范围；步枪、狙击枪和火箭分别验证飞行、镜内显示和范围伤害。核对命中特效、受害者生命和攻击者弹匣。 |
| 换弹与预测 | 分别验证手动换弹、空匣自动换弹、备弹少于缺口、换弹中换枪或开火。观察拥有者的弹药文本最终与权威值一致，其他玩家的换弹动画能随取消结束。 |
| 淘汰与连续重生 | 两端轮流击杀，核对掉枪、布娃娃、计分和新角色的满生命；连续重生后再开火、冲刺、换弹。 |

**有限弹药的判定示例。** 以容量 30、当前 24 发、备弹 4 发为例，一次完整换弹后应显示 28 / 0。用仍有备弹的配置再做一次，在装填完成前开火；先确认换弹被取消，再核对这次射击的消耗。记录换弹前后及服务器弹量到达后的读数，可区分动画中断、重复装填和 HUD 预扣问题。这里的数值用于说明判定方法，实际用例按被测武器表行记录。

历史故障记录已定位两类问题：PlayerState 的低更新频率曾使掉血显示延迟，loose tag 未发布曾使远端动画缺失。现源码保留 100 Hz 设置和显式标签复制。这些属于历史修复证据，本次没有重跑延迟、丢包或双端 PIE。[PlayerState 实现](../Source/TPSCPP/PlayerState/TPSCPPPlayerState.cpp) · [工作区故障记录](../../Docs/Bugs&Resolutions/Bugs&Resolutions.md)
